# Real-document evaluation

The reference covers 260 cells from three selected table bodies across two real
public-domain PDFs. It was visually transcribed by an agent, independently checked
against fresh PDF renders by another agent, and is **not human-certified**.
The first frozen reference had four transcription errors. Both versions and the
explicit post-preliminary-evaluation erratum are retained in
[fixtures/README.md](../fixtures/README.md). This is not a pristine preregistered
benchmark after reference revision.

`extraction.json` is generated by the independent CSV/event verifier after the
browser workflow. It contains every raw mismatch and every effective correction.
No extraction output is treated as ground truth. Sample exports live in
`examples/`; reruns should use a temporary output directory to preserve these.

The synthetic controls in the unit tests are separate from this real-input
benchmark. They test leading zeros, formula-looking strings, CSV quoting,
multiline preservation, encryption, rotation, and image-only rejection. They do
not establish real-world extraction accuracy for those document classes.

These documents are existing upstream pdfplumber example fixtures, not a held-out
corpus. The application uses recorded manual column boundaries; the reported raw
errors therefore describe this configured workflow, not automatic table discovery.

## Observed result

The completed real-document browser run and independent CSV/event verifier found:

| Selected table | Cells | Raw exact-string errors (v2) | Corrected errors (v2) |
|---|---:|---:|---:|
| USDA ethanol | 24 | 16 | 0 |
| USDA biomass | 12 | 0 | 0 |
| FBI NICS, first four columns | 224 | 3 | 0 |
| **Total** | **260** | **19** | **0** |

All rows and columns match the reference order. All 260 cells were explicitly
marked reviewed through browser controls. Sixteen USDA errors are spaces around
price-range hyphens; three FBI errors omit California's visible thousands gaps.
The effective correction count is 19. An extra temporary correction was undone
as a workflow control; its history is retained and separately audited.

Against the original v1 freeze, raw extraction has 20 discrepancies and the final
corrected export has four disagreements, exactly the four documented reference
errata. These counts are retained per table in `extraction.json`.

Validation run on Linux / Python 3.12 with pinned dependencies:

- Core tests: **9 passed** (13.74 seconds in the recorded final core run).
- Focused browser recovery regression: **1 passed** (19.01 seconds).
- Full browser workflow: exit 0, three real tables, 260 cells; correction, review,
  row/column insertion/deletion/reordering with undo, reload, project transfer,
  wrong-source rejection, export, and unsupported-region ledger recovery.
- Independent CSV reader and event replay: **260 ordered cells verified**, source
  and output hashes matched, 19 raw errors and zero corrected errors against v2.

These are actual run results, not estimates. Timing is environment-specific and
is not a performance benchmark. The final geometry rejection guard was covered
by core tests after the long-running browser server had started; it does not
change extraction for the two real input PDFs.
